`rulepack.json` is the manifest for packaging AI memory. It declares identity,
license, visibility, the Markdown memories to ship, and — on the consumer side —
the packs a project depends on. It lives at the project root, like
`package.json`.

<Callout title="Where it lives">
Always at the repository root: `/rulepack.json`. The CLI resolves it from the
current working directory, so a root manifest is what every command expects.
</Callout>

## Coming from package.json

If you've ever written a `package.json`, you already know the shape. The payload
is different: `package.json` ships code; `rulepack.json` ships Markdown memories
for AI agents.

| `package.json` | `rulepack.json` |
| --- | --- |
| ships JavaScript / TS code | ships Markdown memories |
| `name`, `version` | `name`, `version` *(identical meaning)* |
| `license` | `license` *(required for published packs)* |
| npm access / package visibility | `visibility`: `public`, `private`, or `pay` |
| `dependencies` | `dependencies` *(other rule packs)* |
| `files` to include | `files` to include |
| `main` / `exports` entry | `memories` map: files the agent should load |

## Don't write JSON? Let your agent write it

```text title="Paste into your agent"

this repo's AI memory files (AGENTS.md, CLAUDE.md, .cursor/rules, .clinerules,

into one reusable, versioned pack.

Please:
1. Scan the repo and list every existing AI memory file.
2. Create rulepack.json at the project root with:
   - "name": "@<my-scope>/<short-pack-name>" (ask me for my scope)
   - "version": "0.1.0"
   - "license": "MIT" unless I choose another license
   - "visibility": "public" unless I choose private or pay
   - "description": one line on what these memories help an agent do
   - "memories": map existing files to standard keys: agents, claude, cursor,
     cline, windsurf, gemini, copilot. Put other Markdown files under "custom"
     with path and optional description/readWhen/tags.
   - "files": include rulepack.json, LICENSE, README.md, and every memory path.
```

## Example

```json title="rulepack.json"
{
  "name": "@ichi/nextjs",
  "version": "1.4.0",
  "description": "Strict Next.js rules for Claude Code + Cursor",
  "license": "MIT",
  "visibility": "public",
  "keywords": ["nextjs", "typescript", "strict"],
  "memories": {
    "agents": "AGENTS.md",
    "claude": "CLAUDE.md",
    "cursor": ".cursor/rules/main.mdc",
    "custom": {
      "launch-plan": {
        "path": "docs/launch-plan.md",
        "description": "Launch and social media plan",
        "readWhen": "when planning launch posts or growth strategy",
        "priority": "normal",
        "tags": ["marketing", "launch"]
      }
    }
  },
  "files": [
    "rulepack.json",
    "README.md",
    "LICENSE",
    "AGENTS.md",
    "CLAUDE.md",
    ".cursor/rules/**",
    "docs/launch-plan.md"
  ],
  "dependencies": {
    "@rulepack/typescript": "^0.1.0"
  }
}
```

## Fields

| Field | Type | Description |
| --- | --- | --- |
| `name` \* | `string` | `@scope/name`. Lowercase letters, digits, internal hyphens. The scope must be one you own. |
| `version` \* | `string` | Semver. Each published version is immutable — bump it for every release. |
| `license` \* | `string` | SPDX identifier (`MIT`, `Apache-2.0`) or `UNLICENSED`. Ship a matching `LICENSE` file when possible. |
| `visibility` \* | `"public" \| "private" \| "pay"` | Registry access policy. The pack format is identical for all three. |
| `description` | `string` | One line, ≤ 280 chars. Shown in search and on the pack page. |
| `author` | `string` | Optional human-readable author name. |
| `homepage` | `string` | Optional HTTP(S) URL for the source, docs, or project page. |
| `keywords` | `string[]` | Up to 20 tags for discovery. |
| `memories` \* | `object` | Standard memory paths plus optional `custom` project memories. At least one memory is required. |
| `files` | `string[]` | Glob patterns for the published tarball. `rulepack.json` and every declared memory path are always included by the CLI. |
| `dependencies` | `object` | Consumer-side. `@scope/name` → semver range. Written by `rulepack add` when a `rulepack.json` exists. |

<small>\* required for published packs.</small>

## Visibility

| Value | Access |
| --- | --- |
| `public` | Anyone can view metadata, memory files, and install the pack. |
| `private` | Only authorized users or teams can view and install the pack. |
| `pay` | Metadata and the purchase page can be public; memory files and tarball access require purchase. |

Visibility is an access policy enforced by the registry. It does not change the
pack format: all packs still publish `rulepack.json` plus the Markdown files
declared in `memories`.

## The memories map

| Key | Memory | Default path |
| --- | --- | --- |
| `agents` | AGENTS.md | `AGENTS.md` |
| `claude` | Claude Code | `CLAUDE.md` |
| `cursor` | Cursor | `.cursor/rules/main.mdc` |
| `cline` | Cline | `.clinerules` |
| `windsurf` | Windsurf | `.windsurfrules` |
| `gemini` | Gemini CLI | `GEMINI.md` |
| `copilot` | GitHub Copilot | `.github/copilot-instructions.md` |

<Callout title="AGENTS.md is the universal target">
`AGENTS.md` is read by many tools, so `memories.agents` usually covers the long
tail. Add a tool-specific key only when that tool reads its own file.
</Callout>

## Custom memories

Use `memories.custom` for Markdown that is not tied to one agent: plans,
handoffs, architecture notes, launch docs, prompts, or research summaries.

```json
{
  "memories": {
    "agents": "AGENTS.md",
    "custom": {
      "plan": "docs/plan.md",
      "launch": {
        "path": "docs/launch-plan.md",
        "description": "Launch and social media plan",
        "readWhen": "when planning launch posts or growth strategy",
        "priority": "normal",
        "tags": ["marketing", "launch"]
      }
    }
  }
}
```

## Author vs consumer

An **author** manifest requires `name`, `version`, `license`, `visibility`, and
at least one `memories` entry. A **consumer** manifest only needs
`dependencies`; `rulepack add` maintains it for you.

```json title="rulepack.json"
{
  "dependencies": {
    "@ichi/nextjs": "^1.4.0"
  }
}
```

<Callout title="Versioning & provenance">
Published versions are immutable and content-addressed by SHA-256. Provenance is
attested by the registry, not written by the author.
</Callout>
