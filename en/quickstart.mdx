---
title: Quickstart
description: From zero to a published pack in a few commands.
---

You'll need Node ≥ 22. A GitHub account is only required when you publish.

## 1. Scaffold a pack

Run `init` in the project whose memories you want to share. It works without
login, discovers existing agent files, asks which memories the pack should
include, and writes a `rulepack.json` at the root.

```bash title="terminal"
npx rulepack init
```

`rulepack.json` can live in the repo like `package.json`: useful as a local AI
memory manifest even before you publish anything.

## 2. Review rulepack.json

Make sure the generated `name` starts with the scope you plan to publish under
and that every path in `memories` exists.

```json title="rulepack.json"
{
  "name": "@ichi/nextjs",
  "version": "0.1.0",
  "license": "MIT",
  "visibility": "public",
  "memories": {
    "agents": "AGENTS.md",
    "claude": "CLAUDE.md",
    "cursor": ".cursor/rules/main.mdc"
  },
  "files": ["rulepack.json", "README.md", "LICENSE", "AGENTS.md", "CLAUDE.md", ".cursor/rules/**"]
}
```

## 3. Sign in when you're ready to publish

Publishing requires a GitHub session and a claimed scope. Packs live under
`@scope/name`; one account owns one scope, renameable later.

```bash title="terminal"
npx rulepack login
```

This opens your browser, you approve the session, and the CLI stores a token at
`~/.rulepackrc`.

## 4. Publish

Publishing packs the declared files into a tarball, validates the manifest, and
uploads it. Versions are immutable — bump `version` for every release.

```bash title="terminal"
npx rulepack publish
```

## 5. Install anywhere

```bash title="terminal"
npx rulepack add @ichi/nextjs
```

The memory files land in the consumer project and the dependency is recorded in
that project's `rulepack.json`.

<Callout title="No CLI? Use the Hub">
You can create, edit, and publish a pack entirely from the web editor — no local
CLI required. Head to `/packs/new` after signing in.
</Callout>
