_最終更新: 2026-05-31_

scope 名（`@scope`）は、それが表す人物・組織に帰属すべきものです。本ポリシーは、著名な名前をどう保護し、
正規の所有者がどう取得し、認証バッジが何を意味し、スクワッティングやなりすましをどう争うかを説明します。
[コンテンツ/禁止事項ポリシー](/docs/legal/acceptable-use) を補完します。

## 2 種類の保留名

- **予約（Reserved）** — システム/ルート名（`admin`・`api`・`docs` など）とプロジェクト用の名前。誰も取得できません。
- **保護（Protected）** — 著名なライブラリ・企業・製品名（例: `react`・`vercel`・`openai`）。スクワットされないよう保留し、
  下記の手続きで**正規の所有者に解放**します。

いずれかを取得しようとすると、scope 作成は本ページへの案内とともに拒否されます。

## 認証バッジ

**認証済み（verified）** scope（チェックマーク）は、その名前の背後にいる実在の人物・組織を表すことを運営が確認したものです。
保護名が所有者に解放される際に付与され、その他にも確認できた scope に付与されることがあります。これは信頼の指標であり、
個々のパックの内容を保証するものではありません。

## 保護名の取得 / 認証の申請

主な窓口は **GitHub Issue** です（公開チケットとして、申請と対応が透明に残ります）:

1. [LyrraTeam/rulepack-docs](https://github.com/LyrraTeam/rulepack-docs/issues) で
   **Name claim / verification** の Issue を作成。
2. 希望する scope・代表する主体・**確認方法**を記載 —— 例: 一致する GitHub Organization の owner である、
   プロジェクトの公式ドメインやリポジトリを管理している、その他の公開された証明。
3. 運営が確認し、問題なければ scope をあなたのアカウントに割り当て、認証バッジを付与します。

公開できない事項は **contact@rulepack.lyrra.net** へメールしてください —— ただし名前に関しては Issue を推奨します。

<Callout title="1 アカウント 1 scope">
各アカウントは scope を 1 つだけ所有します。組織の認証 scope は専用アカウント（割り当て先）で保持されるため、
すでに別の scope を持っていないアカウントを使う想定でお願いします。
</Callout>

## スクワッティング / なりすましの申し立て

scope やパックがあなたをなりすましたり名前を squat している場合:

- パックページの**通報**ボタン、または Issue、またはメールで連絡してください。
- 対象の scope/pack と、どう侵害しているか（商標・同一性・プロジェクト名）を記載してください。
- 本ポリシーおよびコンテンツ/禁止事項ポリシーに照らして確認します。スクワッティングやなりすましが確認された場合、
  名前を回収して正規の所有者に再割り当てし、問題のコンテンツを削除することがあります。

善意の申し立てに対応します。所有の合理的な証明をお願いする場合があります。

## お問い合わせ

- **名前の取得・認証・紛争:** GitHub Issue（推奨）。
- **非公開・機微な事項:** **contact@rulepack.lyrra.net**。
