このページは、実際のリポジトリで `rulepack.json` を作るための手順です。全フィールドの
完全なリファレンスは [`/rulepack.json`](/rulepack.json) にあります。

## 1. まず agent がすでに読んでいるファイルを探す

AI coding agent を導いている Markdown files を探します。

```text title="your-project/"
.
├── AGENTS.md
├── CLAUDE.md
├── .cursor/
│   └── rules/
│       └── main.mdc
├── docs/
│   └── plan.md
└── README.md
```

rulepack では、これらを **memories** と呼びます。`CLAUDE.md` のように特定ツール向けの
ものもあれば、`docs/plan.md` のように project context として使うものもあります。

## 2. agent に manifest の下書きを作らせる

Claude Code、Cursor、Codex などの coding agent にこれを貼り付けます。

```text title="エージェントに貼り付け"
このプロジェクトに rulepack.json をセットアップして。

rulepack.json は package.json に似ているけど、コードの代わりに、このリポジトリの
AI memory ファイル（AGENTS.md / CLAUDE.md / .cursor/rules / .clinerules /
.windsurfrules / GEMINI.md / Copilot instructions / custom Markdown docs）を、
再利用・バージョン管理できる 1 つのパックにまとめるもの。

お願い:
1. リポジトリを調べて、すでに存在する AI memory ファイルを全部挙げて。
2. プロジェクト直下に rulepack.json を作成して、次を含めて:
   - "name": "@your-scope/short-pack-name"（scope は私に聞いて）
   - "version": "0.1.0"
   - "license": "MIT"（別のライセンスを選ぶなら聞いて）
   - "visibility": "public"（private / pay にするなら聞いて）
   - "description": これらの memories が AI に何を助けるかを 1 行で
   - "memories": 既存ファイルを標準キー agents, claude, cursor, cline,
     windsurf, gemini, copilot に対応づけて。その他の Markdown は "custom"
     に path と任意の description/readWhen/tags 付きで入れて。
   - "files": rulepack.json, LICENSE, README.md, すべての memory path を含めて。
3. 作成したファイルを見せて、各フィールドをやさしい言葉で説明して。

参考: https://rulepack.lyrra.net/rulepack.json
```

<Callout title="placeholder を具体的にしている理由">
角括弧を含む scope/name placeholder は使わず、
`@your-scope/short-pack-name` のように書きます。一部の docs / translation system は
`<...>` を tag として扱うため、具体的な placeholder の方が安全に copy できます。
</Callout>

## 3. 生成された rulepack.json を確認する

典型的な出力はこうなります。

```json title="rulepack.json"
{
  "name": "@ichi/nextjs",
  "version": "0.1.0",
  "description": "Next.js project memory for AI coding agents",
  "license": "MIT",
  "visibility": "public",
  "keywords": ["nextjs", "typescript"],
  "memories": {
    "agents": "AGENTS.md",
    "claude": "CLAUDE.md",
    "cursor": ".cursor/rules/main.mdc",
    "custom": {
      "plan": {
        "path": "docs/plan.md",
        "description": "Project plan and implementation notes",
        "readWhen": "before planning major implementation work",
        "priority": "high",
        "tags": ["planning", "handoff"]
      }
    }
  },
  "files": [
    "rulepack.json",
    "README.md",
    "LICENSE",
    "AGENTS.md",
    "CLAUDE.md",
    ".cursor/rules/**",
    "docs/plan.md"
  ]
}
```

公開前に、まずこの 3 点を確認します。

- `memories` に書いた path がすべて存在する。
- `files` に README、LICENSE、追加の補助ファイルが含まれている。
- `visibility` が意図どおり: `public`、`private`、`pay`。

## 4. standard memories と custom memories を分ける

標準 memory keys は、各 tool が慣習的に読むファイルを指します。

| キー | ファイル |
| --- | --- |
| `agents` | `AGENTS.md` |
| `claude` | `CLAUDE.md` |
| `cursor` | `.cursor/rules/main.mdc` |
| `cline` | `.clinerules` |
| `windsurf` | `.windsurfrules` |
| `gemini` | `GEMINI.md` |
| `copilot` | `.github/copilot-instructions.md` |

`memories.custom` は、agent をまたいで役立つ project-level Markdown に使います。計画、
引き継ぎ、設計メモ、launch docs、prompt、調査メモ、runbook などです。

短く path だけでも書けます。

```json
{
  "custom": {
    "plan": "docs/plan.md"
  }
}
```

metadata 付きにもできます。

```json
{
  "custom": {
    "launch": {
      "path": "docs/launch-plan.md",
      "description": "Launch and social media plan",
      "readWhen": "when planning launch posts",
      "priority": "normal",
      "tags": ["marketing", "launch"]
    }
  }
}
```

## 5. 公開するか、local で使う

他の project でも install できるようにするなら publish します。

```bash title="terminal"
npx rulepack publish
```

project に導入した packs を記録するだけなら、`rulepack add` が consumer-side manifest を
維持します。

```json title="consumer rulepack.json"
{
  "dependencies": {
    "@rulepack/nextjs": "^0.1.0"
  }
}
```

consumer manifest は最小で構いません。その project 自体が pack を公開しないなら、
`name`、`version`、`memories` は不要です。
